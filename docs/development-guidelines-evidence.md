# 开发规范的历史改动依据

本记录对照仓库中保留的贡献版本与后续修复、重构或集成版本，用于解释[开发规范](development-guidelines.md)中部分规则的来源。比较截至本地 `caa6957`；不包含尚未提交的业务代码，也不声称覆盖所有历史 PR。

作者、改动及集成关系以本地 Git 对象为依据，未采用线上评审讨论。PR 编号只使用合并记录可确认的关系；分支名不足以证明原始 PR 的编号。提交链接用于查阅对应版本。

下述“观察”是可由差异确认的事实，“提炼”是据此提出的通用审查要求。重构包含功能取舍，不表示被删除的功能永远不允许，也不将原版本的所有设计都视为问题。

## 1. 公共能力的依赖方向与复用层次

**对照：** 全局拖拽贡献版本 [`38b0991`](https://github.com/LumiaGG/GestureEVO/commit/38b0991) → 维护者 [`7607d75`](https://github.com/LumiaGG/GestureEVO/commit/7607d75)、[`947227b`](https://github.com/LumiaGG/GestureEVO/commit/947227b)。前者及其前序拖拽提交作者为 wyxa，后两者作者为 LumiaGG。

**观察：** 悬浮窗基类原来引用 `drop.SourceTouchRegions`，后将注册表移入 `floating.OverlayTouchRegions`。进程流实现原位于 `DiagnosticRelay`，并承载触摸流所需的租约等参数；重构提取 `utils/process` 中的传输、命令和行读取能力，诊断层保留 `GEVO_END` 等业务协议。

**提炼：** 公共基础设施不反向依赖具体功能；复用通用机制时提取机制本身，不能让其他功能被迫依赖诊断或拖拽语义。对应规范第 1 节。

## 2. 拆分职责、按需初始化与后端收敛

**对照：** 同一全局拖拽贡献版本 → 维护者 [`5821c1f`](https://github.com/LumiaGG/GestureEVO/commit/5821c1f)、[`76e16b8`](https://github.com/LumiaGG/GestureEVO/commit/76e16b8)、[`19c5770`](https://github.com/LumiaGG/GestureEVO/commit/19c5770)、[`9b640d1`](https://github.com/LumiaGG/GestureEVO/commit/9b640d1)、[`98517c7`](https://github.com/LumiaGG/GestureEVO/commit/98517c7)。

**观察：** 转换会话、外观、配置、内容解码与分发分别提取；Shizuku 连接与触摸流管理分离，权限申请进入设置操作，连接后端只使用已有授权。随后删除平行 Root 后端并复用 Shizuku。内容识别与触摸中断后移至拖拽激活后的准备阶段，指针和拖拽的选区采集统一至共享入口。

**提炼：** 大型协调类不包办数据、渲染和平台后端；昂贵或有副作用的能力按已确认需求启用；后台不自行申请权限；第二套后端须有实际必要性；同类采集路径复用共同策略。这里不将“禁止 Root”或“禁止提前采集”写为绝对规则，确有需求的例外应明确边界。对应第 1、3、6、7.4 节。

## 3. 配套功能的必要性与存储类型

**对照：** 链接功能贡献提交 [`13e5006`](https://github.com/LumiaGG/GestureEVO/commit/13e5006)、[`52937c5`](https://github.com/LumiaGG/GestureEVO/commit/52937c5)（cnsry00-stack）→ 维护者 [`18571f2`](https://github.com/LumiaGG/GestureEVO/commit/18571f2)、[`0be0cac`](https://github.com/LumiaGG/GestureEVO/commit/0be0cac)。本地 `970ef07` 记录将后者作为 PR #67 合入。

**观察：** 原 `LinkHistoryRepository` 将最多 200 条历史保存为 DataStore 的单个 JSON 字符串，写入流程是先加载、去重、追加，再整体保存。重构删除该历史存储及配套面板，同时移除独立震动实现并复用现有能力；没有将历史迁入新数据库表。

**提炼：** 移植功能不等于必须带入上游配套功能；历史记录即使有条数上限，也不能只据此选用偏好存储。需求成立时按数据行为设计存储；需求不足时可以删减。不能把此次变化描述成“历史改用 Room”。对应第 1、2.2 节。

## 4. 原子修改与一次性初始化

**对照：** 上述链接贡献版本 → `18571f2`、`0be0cac`。

**观察：** 原调用方先加载规则、修改后整体保存，导入分别保存规则、豁免和提取配置；重构提供基于最新值的 `updateRules`、单份配置快照及单次 `edit` 导入。内置数据初始化把内容写入与已初始化标记合并；旧域名迁移补充保留既有规则和子域名优先关系的逻辑。`LinkPersistenceTest` 新增并发追加、统计与开关并发修改、转换失败保留旧数据的验证。

**提炼：** “一次保存不会写一半”不足以保证读改写一致性；多个相关值应按同一快照读取、整体提交。初始化不能以集合为空推断，用户删除必须保留；迁移除字段外还需保留实际规则顺序。对应第 2.2、2.4、6、7.1 节。

## 5. 最小会话范围、预览与已接受命令

**对照：** 上述链接贡献版本 → `18571f2`、`0be0cac`。

**观察：** 雷达实现从轮询、重扫调度及大量会话标记，收敛为会话内扫描与指针位置通知；节点与字符位置读取复用既有采集机制。目标预览使用实际本地路由规则，但关闭短链网络解析。预览随会话关闭取消，已接受的打开动作明确交给 Service 作用域执行。

**提炼：** 先减少需要做的工作，再选择轮询或事件；事件驱动不等于应全局监听所有变化。预览共享业务规则但不自动执行外部探测；命令确认后可交接所有者，其生命周期不必等同预览。此次收敛不推出“所有扫描永远只做一次”，需要动态刷新时仍须说明失效条件。对应第 3、4、7.4 节。

## 6. 完整执行链与响应监听时序

**对照：** 链接功能启动实现 → `0be0cac` 中的 `LinkLauncher`、`ActionProxy` 和代理 Activity 改动。

**观察：** 原链接启动借用窗口参数后直接启动 Activity；重构将完整 Intent 序列化后交给 `ActionProxy.executeLink`，携带触发侧并接入原有执行链。代理结果等待原来在 `startActivity` 后订阅；重构用立即启动的异步等待先建立监听，再启动 Activity，并在结束时取消等待。

**提炼：** 复用末端工具不等于复用兼容链；代理传递不能丢失组件、extras、flags 和上下文。无重放事件必须先监听再触发，请求响应要覆盖立即返回、超时及取消。对应第 4、7.4 节。

## 7. 多阶段规则与降级不能改变语义

**对照：** 链接功能贡献版本 → `18571f2`、`0be0cac` 及新增回归测试。

**观察：** 路由回归覆盖相对重定向、循环和过长链、重新分发后的豁免、缺少来源正文时的捕获组，以及包含占位符的替换值不能再展开。扫描重构保留 URLSpan 元信息，并区分字符定位“不支持”与“支持但没有可见字符”；后者不退回整框命中。

**提炼：** 转换目标后重新校验策略；管线有界；替换数据不再次解析成语法；去重保留语义元信息；降级必须区分能力缺失和有效空结果。对应第 7.5 节。

## 8. 框架兼容应提炼策略并验证边界

**对照：** PR #34 的贡献提交 [`1c66a79`](https://github.com/LumiaGG/GestureEVO/commit/1c66a79)、[`bb984af`](https://github.com/LumiaGG/GestureEVO/commit/bb984af)（wyxa）→ 维护者 [`4392614`](https://github.com/LumiaGG/GestureEVO/commit/4392614)。本地 `c646f98` 明确记录 PR #34 与 Flutter 提取修正的集成关系。

**观察：** 后续修改不仅调整节点遍历，还提取 `AccessibilityTextPolicy`、`AccessibilityTextHierarchy` 及测试。策略根据文本、描述、交互能力和层级关系判断正文，覆盖 Flutter 静态描述文本、按钮标签和父子汇总去重。

**提炼：** 框架差异处理应表达可测试的策略，不只堆积类名特判；外部字段的语义需结合能力与上下文。策略测试覆盖边界，系统行为仍需对应环境验证。对应第 1、7.5、8 节。

## 9. 补充样本与归因边界

- PR #51 的 `67384aa`、`ee199d9` 分别修复搜索完成回调与模式选择恢复，但两者均由贡献者 wyxa 完成；不能将这些修复称为维护者重构。它们支持规范中所有权、完成语义、恢复状态和防重复提交的已有要求。
- PR #52 的 `2d4d030` → `3f62824` → `9ffe7f8` 也均由 wyxa 完成。后续修复扩展到附属视图、输入框状态色、开关轨道及轮廓，支持“主题刷新覆盖完整状态”的通用要求，不归因于维护者。
- PR #53 的 `7c00b7b` → 维护者 `21452a0` 主要是新增悬停状态回归测试，没有据此宣称业务实现被重构或存在已确认缺陷。
- `8585947` 的键盘搜索修复区分持久化键串与运行时查询，并在目录同步完成后使用当前输入刷新。这是现有系统扩展后的维护案例，支持接口表示与状态快照规则；本文不将其强行归为某个第三方 PR 的缺陷。
- `970ef07` 的集成记录明确保留全局拖拽长点击事件。共享系统事件与入口的改动应核对其他调用方；合并无冲突不代表组合行为正确。

## 10. 如何复核

使用 `git show <提交> -- <路径>` 核对单次修改；对同一功能可用 `git diff 52937c5 0be0cac -- app/src/main/java/io/github/lumiagg/gestureevo/link` 等命令对照最终实现。后者区间含中间提交，不能把区间内所有变化都归因于单个 PR。

本文是历史差异分析，不是旧版本运行结果或当前实现全面合规的证明。复核源码差异不能代替变更所需的构建、测试与设备验证；正式审查要求以开发规范为准。
