# 日志与故障反馈

入口：设置 → 数据 → 日志管理器，也可在设置中搜索“日志”。

1. 点击“开始记录问题”；日志暂停时，点击“开启并记录问题”即可一并开启。会自动开启详细诊断，并为本次复现生成随机问题编号，最长记录 30 分钟。运行日志和详细诊断开关在顶部状态按钮或右上角菜单的“记录设置”中。
2. 后台启动类问题可点“系统诊断”，选择已有授权的 Shizuku 或 Root，再离开页面复现问题。系统日志通过连续管道读取，最多持续约 60 秒、2 MB 原始流或 1000 条相关事件，可提前停止；原始消息不会保存到磁盘。过长单行会跳过并计数。未授权、连接超时、服务断开、命令失败和采集达到上限会分别显示。
3. 返回管理器，点击“结束并导出”，选择分享或保存文件，默认只包含本次问题。结束后恢复开始前的详细诊断时限；手动调整详细诊断时会尊重您的选择。进程重启后未结束的问题会标记为中断，最近 20 次问题记录可通过“历史记录”选择查看。
4. 点击筛选标签可选择模块、级别或时间范围，也可搜索事件标识、包名或关联编号。顶部导出按钮可导出当前筛选结果、全部日志或指定 `trace` 关联编号。列表显示简短摘要，点击单条日志可查看完整事件标识、编号和堆栈，并通过“导出关联动作”直接导出相同编号的记录。
5. 反馈时补充复现时间、操作步骤和预期结果。点击存储与状态一行可查看文件容量、最近错误、本进程写入队列、丢弃数量和写入失败，帮助判断日志是否完整。清空操作位于右上角菜单，执行前会再次确认。

`launch_request_submitted` 表示启动调用返回，不代表目标 Activity 已显示或 MacroDroid 宏已执行。系统诊断中的 `background_launch_blocked`、`permission_denied` 是对匹配系统消息的分类；没有匹配消息不能证明启动被允许。不同系统的日志内容和可访问范围可能不同。

日志默认只在本机保留，单文件上限 2 MB，所有进程与崩溃日志合计上限 20 MB，最长保留 7 天。崩溃记录为独立文件，不依赖崩溃页面成功显示。原生崩溃、系统直接杀进程等情况不保证产生 Java 崩溃记录。

导出包含 `environment.txt`、`scope.txt` 与 JSONL 日志，不包含应用配置备份。范围说明不会保存搜索关键词。只记录白名单元数据，不记录完整链接、Intent extras、Shell 命令、截图/OCR 正文、联系人和账号凭据；异常保留类型、调用位置和可明确提取的 HTTP 状态码、errno、网络失败分类，不记录异常消息。设备型号、版本、动作目标包名和组件仍会出现在导出中。

查看日志时维护文件偏移与元数据索引，新增记录增量解析，最近记录使用有上限的缓存；文件变化时才自动刷新。导出先固定各文件的字节长度并持有读取句柄，再在写入队列之外复制，避免复制全部日志时阻塞后续日志。

开发时用 `AppLogger.event(LogModule.ACTION, "event_name", fields = ...)` 写入持久化日志。事件名称使用固定英文标识，字段通过 `LogPrivacy` 白名单。不要将用户内容放入事件名、关联编号、线程名或组件名。DEBUG 记录仅在详细诊断期间写入。现有 Android `Log.*` 不会自动复制到文件；新增排障点应显式使用此接口。
