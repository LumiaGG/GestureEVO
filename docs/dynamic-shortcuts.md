# 动态快捷方式导入

入口：设置 → 快捷工具 → 动态快捷方式（Android 7.1 起）。

1. 点击“临时设为默认桌面”，在系统界面选择 GestureEVO 快捷方式导入。
2. 返回导入页，点击“读取并选择快捷方式”，勾选所需入口后导入，也可以全选。
3. 点击“切回原桌面”，在系统界面选择平时使用的桌面。按 Home 时，临时桌面会回到导入页，方便完成切换。
4. 已导入列表支持轻点启动、长按复制动作链接。在手势或轮盘的快捷方式来源中，选择“动态快捷方式”即可配置。

只读取系统当前公开的动态快捷方式及 EVO 已固定的入口，不会启动目标应用生成新入口。重新读取或固定新入口需要再次取得桌面权限；切回原桌面后，EVO 此前固定的入口仍可通过系统接口启动。目标应用禁用入口、卸载、清除数据或资料空间不可用时，启动仍可能失败。

## 数据与恢复

引用按包名、shortcut ID、用户序列号区分，存入现有 Room 数据库的独立表；数据库 1 → 2 迁移仅新增此表，保留现有配置与记录。不同资料空间的同名入口不会合并。系统设置快捷方式索引重建不会影响导入记录。

导入按应用与资料空间分组，合并 EVO 已固定的 ID 后再调用 `pinShortcuts`，避免替换旧入口。先暂存元信息，再固定并读取系统结果，确认固定成功后才在本地标记可用。若中断发生在系统固定成功与本地确认之间，再次读取会确认已暂存且已固定的记录；部分失败保留此前成功的组，允许重新选择重试。系统拒绝或查询失败不会以成功空列表覆盖本地记录。

这是本机系统授权的引用，不加入应用的本地／WebDAV 配置备份。动作链接沿用现有配置备份；恢复到另一设备后须重新导入对应入口，不能通过动作链接恢复固定授权。Android 自身的数据恢复即使带回元信息，也仍由系统在每次启动时验证固定关系。

查询和导入仅由设置页明确操作触发，无后台轮询。任务由页面 ViewModel 管理，旋转屏幕不重复导入；退出页面会取消任务。其他资料空间由系统检查可访问性，读取前需解锁。启动复用 ActionProxy 的追踪、当前用户应用解冻、应用打开统计与小窗选项，系统权限失败会提示重新导入。

## 图标与小窗

图标配置随应用启动，从已有偏好快照初始化，不依赖先打开主入口或启动无障碍服务。列表与选择器使用全局图标包、应用图标覆盖及圆角；轮盘使用同一图标来源，但保留轮盘自己的图片圆角、背景圆角和边距设置。

普通链接、应用页面与系统动态快捷方式共用 ActionProxy 的 ROM 小窗路由。标准系统使用窗口选项；vivo 进入既有分享选择器／代理协议，再由不导出的内部页面继续调用系统 shortcut 启动接口。小窗位置在进入分享流程前固定，保留 shortcut ID、资料空间及系统固定关系；成功结果以实际提交 shortcut 启动请求为准，不以代理页面打开为准。待执行请求仅存于本进程，单次消费，10 秒超时或取消后清除，页面重建不重复执行。

Nubia／红魔协议需要修改目标页面的 Intent identifier，系统动态快捷方式不公开此 Intent，因此该组合明确提示不支持，不替换成普通应用启动。Mi-FreeForm 插件的原有包名／页面启动协议保持现有普通应用范围。以上属于代码路由核对，vivo 的小窗实际效果仍需真机验证。

## 验证范围

JVM 测试覆盖保留旧固定项、重复导入、固定失败、无声失败、用户隔离与取消。设备测试覆盖旧版数据库迁移、旧记录保留、暂存／确认以及重复导入。

真机需验证：拒绝桌面请求、设为默认桌面后读取、选择／全选导入、切回原桌面后启动、旋转与进程中断后的重试、工作资料锁定、目标入口禁用／卸载、手势与轮盘启动。不同 ROM 的默认桌面选择及后台启动限制需分别验证。
